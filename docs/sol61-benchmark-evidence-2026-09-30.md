`rejectedScope` list. The scorer checks the selected scope, requires all five
unsupported scope IDs, and rejects a scope that is both selected and rejected.
It no longer rejects words found anywhere in a free-text chunk title. The case
and prompt are revision 3; the suite is revision 2; the scorer is revision 3;
normalizer and behavioral contract are unchanged. Evidence bindings were
regenerated. Earlier result files were preserved outside Git.

Regression fixtures distinguish a safe selection that explicitly excludes
“Issue #86 Floor observation schemas,” actual selection of unsupported Floor
work, contradictory selected/rejected scope, missing scope fields, and malformed
JSON. The historical wording check is a scorer regression fixture, not a fresh
model result.

The native receipt still preserves requested identity separately from served
identity. Missing, contradictory, or fallback-unknown telemetry remains
non-comparable. Missing/malformed CLI telemetry has a native infrastructure
failure kind and remains an operational transport limitation with
`modelConclusion:null`. Native identity fixtures cover missing identity,
missing fallback status, inconsistent identity, explicit fallback, and valid
identity plus explicit no-fallback evidence.

## Proposed role and effort map

This is an operator recommendation, not a production policy edit. It follows
the current driver/worker guidance and role policy; it is not a ranking from the
invalid two-call screen. Prefer the lowest capable effort, and compare total
correct-completion cost including retries, review, latency, and maintainer
attention.

| Work and router role | Proposed participant and effort | Rail | Exact fallback | Use |
|---|---|---|---|---|
| Routine evidence gathering and planning (`research-fast`) | `gpt-6-luna` / medium | Codex CLI, included subscription | `gpt-6-sol` / medium; Codex CLI subscription | Keep Luna on the existing rung; escalate when evidence conflicts. |
| Substantive coordination and prompt preparation (`architect`; human driver) | `gpt-6-sol` / medium | Codex CLI, included subscription | `gpt-6-astra` / medium; Codex CLI subscription | Keep coordinator judgment with the driver; do not make workers inherit its model. |
| Unresolved architecture (`architect`) | `gpt-6-sol` / medium | Codex CLI, included subscription | `gpt-6-astra` / medium; Codex CLI subscription | For particularly difficult architecture, request `gpt-6-astra` / high directly and use `gpt-6-sol` / high as its fallback. |
| Review coordination (`review-coordinator`) | `gpt-6-sol` / medium | Codex CLI, included subscription | `gpt-6-astra` / medium; Codex CLI subscription | Keep coordination separate from bounded review workers. |
| Routine bounded review (`review-fast`) | `gpt-6-luna` / medium | Codex CLI, included subscription | `gpt-6-sol` / medium; Codex CLI subscription | Preserve family-independence requirements when a second perspective is required. |
| Substantive bounded review (`review-deep`) | `gpt-6-sol` / medium | Codex CLI, included subscription | `deepseek/deepseek-v4-pro-0813` / medium; OpenRouter API | Use an independent eligible family as the existing next rung. |
| Bounded implementation (`builder-fast`) | `gpt-6-luna` / high for settled work | Codex CLI, included subscription | `gpt-6-sol` / high; Codex CLI subscription | Keep Sol as the existing builder fallback; use Astra only when task evidence justifies it. |
| Difficult debugging or judgment (`builder-deep`) | `gpt-6-astra` / high when uncertainty is named | Codex CLI, included subscription | `gpt-6-sol` / high; Codex CLI subscription | Retain Astra where stronger completion quality can reduce retries and review cost. |

The requested `gpt-6.1-sol` / low and medium cells remain challengers, not
proposed production rungs. Low versus Medium still requires valid evidence on
the four requested cases and a separately authorized production canary. Keep
GPT-6 Sol as the current baseline/fallback; this work provides no basis to
promote GPT-6.1, demote Sol, or change any production role order.
