Converged authority correction

A broad one-touch run is not safe for same-UID automated callers. SO_PEERCRED identifies a UID, not which code under that UID spends authority. M1 therefore authorizes exactly one final OpenRouter request body per FIDO UP+UV assertion. The assertion covers the final body digest and complete destination/model/repository/run/lane/candidate/policy/time/replay scope. A competing same-UID process cannot substitute another body, and exact replay sends at most once.

This is the smallest safe request, not unattended multi-request automation. A later milestone must add a distinct client principal or equivalent non-transferable capability before one approval can cover dynamically generated requests.

Non-negotiable M1 tests

  • Wrong/missing UP/UV, RP ID, credential generation, body digest, origin, path, model order, repository, run, lane, candidate, policy digest, nonce, issuance, expiry, signer, boot/session, or sequence fails before network contact.
  • A same-UID competing process cannot replace the approved body; concurrent exact duplicates send at most once; restart after send_started produces outcome_unknown with no retry.
  • Missing/wrong libfido2 1.17.0 ABI, stub build, host-PIN authenticator, redirected/changed/missing controlling TTY, device removal, cancellation, and timeout never report production ready.
  • Caller key/base/proxy/socket/client/scanner/policy/output/auth-mode/digest values are ineffective. Scanner rejection and all pre-send mismatches produce zero fixture-server requests.
  • Credential, prompt, response, assertions, and private signing bytes are absent from argv, environment, logs, files, receipts, crash output, children, and sibling reads.
  • Only the assessment lane is enabled. Research, adversarial review, execution, dm-review, Airlift, unknown/missing lanes, and ordinary developer checkout preserve explicit Codex fallback.
  • Real FIDO hardware, root systemd lifecycle, production credential, system TLS/OpenRouter, macOS, Docker substrate, and repository verification remain live gaps and cannot be mocked as passes.
