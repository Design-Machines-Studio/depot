# Content-based disclosure filter

Loaded only when an OpenRouter lane is dispatched. Codex and Claude lanes
receive the complete review diff and never load this file.

### Content-Based Disclosure Filter

File names such as `.env`, `*credentials*`, `*secret*`, `*.key`, and `*.pem`
are risk signals, not disclosure evidence. Do not strip content by path name.
The independent non-implementing-family security sign-off receives the complete diff.
Kimi K3 receives every file section emitted by the OpenRouter disclosure
boundary; only held paths receive additional same-agent local coverage.

Immediately before any OpenRouter mechanical lane, run the installed
OpenRouter delegation boundary over the exact immutable diff snapshot. A safe
documentation placeholder, explicit provider-prefixed `not-for-proof` test
sentinel, variable name, or non-secret auth, security, deployment, `.env`, or
credential-handling implementation remains eligible regardless of its path. A high-confidence
credential, complete private-key block, authenticated DSN, classified private
data, malformed diff, symlink diff, or prohibited execution authority declines
that OpenRouter disclosure while local review continues.

For a partial decision, keep the OpenRouter result and report content-free
counts followed only by the held paths needed for local coverage:

```text
OpenRouter reviewed 6 eligible file sections; 1 section remained local.
Closed reason: high-confidence-credential.
Local coverage path: tests/integration/compose-release-command.sh
```

Use a full-decline message only when no eligible remainder exists or the exact
outbound prompt still contains refused bytes. Report one closed reason and one
next action; never claim no code was sent after a partial dispatch.
